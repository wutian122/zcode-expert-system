# /wf:design

## 前置

必须先有 `/wf:triage` 的分类结论。**未分类不得进本阶段。**

## 执行

1. 探查上下文（有 `.codegraph` 先 `codegraph_explore`）
2. 按三层清单澄清，**一次一个问题**
3. 出 2–3 方案 + 推荐 + 理由
4. 分节展示设计（架构 / 组件 / 数据流 / 错误处理 / 测试）
5. 自审：占位符 / 一致性 / 范围 / 歧义
6. **等老板明确 yes**

## 三层澄清清单

**业务**：解决什么问题 / 谁用 / 怎么触发 / 正常流程 / 异常处理

**技术**：涉及模块 / 新增 API / 改数据库 / 引入依赖 / 权限安全 / 影响现有功能

**测试**：正常场景 / 异常场景 / 边界条件 / 集成测试 / 浏览器验证

## HARD-GATE

**未经老板批准的设计，不得写任何代码。**
对每条路径都成立，包括"太简单不需要设计"的自我豁免念头。

## 关键约束：不落盘（R3 / W2）

**本阶段不写任何设计文档文件。**

- 中/大任务：唯一设计真相 = S2 的 `design.md`
- 小任务（不走 OpenSpec）：才落 `docs/superpowers/specs/`，**首行必须标注**「非权威：本文件不承载验收」

理由：brainstorming 技能默认会写 `docs/superpowers/specs/`，与 OpenSpec `design.md` 形成两个设计真相。必须显式覆盖。

## 退出条件（G1）

- [ ] 老板明确 yes
- [ ] 2–3 方案对比 + 推荐理由
- [ ] 验收标准已成文
- [ ] 明确"不包含什么"
- [ ] `docs/superpowers/specs/` 无本次新增文件

## 失败返回点

- 老板否决 → 重出方案
- 老板改需求范围 → 回 `/wf:triage` 重分诊（**ratchet，不降级**）
