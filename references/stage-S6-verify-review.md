# S6 · 验证审查

**门禁**：G6（审查）+ G7（验证）｜ **证据级**：P3 ｜ **角色**：Reviewer（异域专家）

## 五层验证（按任务属性取用）

| 层 | 查什么 |
|---|---|
| **一 质量检查** | 编译 / Lint / 类型 / 静态分析 / 依赖安全 / 格式 |
| **二 单元测试** | 核心逻辑 / 工具类 / 数据处理 / 参数校验 / 异常 / 边界 |
| **三 集成测试** | 模块调用 / 数据库访问 / API / 第三方服务 / 事务一致性 |
| **四 系统测试** | 完整业务流程 / 异常流程 / 权限 / 数据状态 / 并发 / 边界输入 / 兼容性 |
| **五 专项** | 按属性标签触发（见下） |

### 专项四域（属性标签触发）

| 标签 | 追加验证 |
|---|---|
| **前端 UI** | 页面加载 / 交互 / 表单校验 / 网络请求 / 控制台无异常 / 多分辨率。浏览器验证走内置浏览器，**主代理亲为** |
| **后端** | API 返回结构 / 参数校验 / 权限 / 异常处理 / 日志 / 事务 |
| **数据库** | 迁移 / 字段类型 / 索引 / 外键约束 / 数据一致性 / **回滚验证** |
| **安全** | 认证 / 授权 / 输入过滤 / SQL 注入 / XSS / 敏感信息泄露 / 文件上传 |

## 终审

```bash
bash "${ZCODE_PLUGIN_ROOT}/skills/zcode-expert-system/scripts/sdd/review-package" <plan> <MERGE_BASE> <HEAD>     # 有 git
```

用 `references/roles/reviewer.md` 模板（双结论：spec 符合性 + 代码质量），最强档专家。审查报告写 `review-<N>.md`，对照 `templates/review-report.md` 输出。

**只做一轮修复 wave + 一次 scoped 重审**。残余裁决向上汇报，不做第二轮。

## 审查结论三态

`APPROVED` / `NEEDS_FIX` / `BLOCKED`

发现问题后实施者修改 → **必须重审**。

## 审查独立性（必须落盘）

| 级别 | 含义 | 可交付 |
|---|---|---|
| `L0` | 独立子代理审查 | ✅ |
| `L1` | 主控自审降级（须显式声明） | ✅ |
| `L2` | 无审查 | ❌ **禁止交付** |

落盘位置：ledger + 计划文档 `## Review` 段（`independence: L0`）。

## verification 门函数（5 步，不可省）

1. **识别**证明命令
2. **完整运行**（不是抽样）
3. **读输出与退出码**
4. **核对**输出是否支持声明
5. **才开口**

禁止：没跑就说通过 / 只看汇报就认为完成 / 只跑部分说全部 / 拿历史结果当本次证据。

## 退出条件（G6 + G7）

- [ ] 五层验证按属性全过
- [ ] verification 门函数 5 步已在本会话执行
- [ ] 审查独立性已标记 L0/L1/L2
- [ ] **Rulings 全量清单已写入计划文档 `## Rulings`**（防 workspace 删除后丢失）
- [ ] 审查结论已写入 `## Review`
- [ ] Critical/Important 已修或已裁决

## 失败返回点

| 失败 | 返回 |
|---|---|
| Critical/Important | 回 S5，**仅一轮**修复 wave |
| 修复 wave 后仍 open | 残余裁决 → 汇报老板，无第二轮 |
| 验证红 | 回 S5 对应任务，不得带红进 S7 |
| 证据缺失 | 不得声明完成，回 S5 |

## 审查清单（8 项）

需求符合性 / 代码质量 / 安全性 / 异常处理 / 数据一致性 / 接口兼容 / 测试质量 / 回归风险
