# S1 · 需求澄清与方案设计

**门禁**：G1（**停老板**）｜ **证据级**：无（不落盘）｜ **角色**：Orchestrator + 域专家会诊

## 输入

- S0 分诊结论
- 三层澄清清单（业务 5 / 技术 6 / 测试 5）

## 动作

1. 检查现有项目结构与相关代码（有 `.codegraph` 先 `codegraph_explore`）
2. 按三层清单澄清，**一次一个问题**
3. 出 2–3 方案 + 推荐 + 理由
4. 分节展示设计（架构 / 组件 / 数据流 / 错误处理 / 测试）
5. 自审：占位符 / 一致性 / 范围 / 歧义
6. **等老板明确 yes**

### 三层澄清清单

**业务**：解决什么问题 / 谁用 / 怎么触发 / 正常流程 / 异常怎么处理

**技术**：涉及哪些模块 / 是否新增 API / 是否改数据库 / 是否引入第三方依赖 / 是否涉权限安全 / 是否影响现有功能

**测试**：正常场景怎么验 / 异常场景怎么验 / 边界条件 / 是否需要集成测试 / 是否需要浏览器验证

## 退出条件（G1）

- [ ] 老板明确 yes
- [ ] 2–3 方案对比 + 推荐理由
- [ ] 验收标准已成文
- [ ] 明确"不包含什么"
- [ ] `docs/superpowers/specs/` **无本次新增文件**

## 失败返回点

| 失败 | 返回 |
|---|---|
| 老板否决 | 回 S1 重出方案 |
| 老板改需求范围 | 回 S0 重分诊（ratchet） |

## 关键约束：不落盘（R3 / W2）

**阶段一不写任何设计文档文件。** 设计在对话内分节展示、分节批准。

- 中/大任务：唯一设计真相 = S2 的 `design.md`
- 小任务（不走 OpenSpec）：才落 `docs/superpowers/specs/`，且**首行必须标注**「非权威：本文件不承载验收」

理由：brainstorming 技能默认会把设计写到 `docs/superpowers/specs/`，与 OpenSpec `design.md` 形成两个设计真相。必须显式覆盖技能默认。

## HARD-GATE

**未经老板批准的设计，不得写任何代码。** 对每条路径都成立，包括"太简单不需要设计"的自我豁免念头。
